Field notes

  1. 1 Role-tagged roster. Every candidate carries a role chip (Product Owner / Engineer), filterable by the same tabs. A candidate mechanism for assigning the roles this discovery's MVP scope already calls for.
  2. 2 You're pre-included. The operator's own row is added by default and grouped by role — attribution starts here, before anyone else is picked.
  3. 3 Save as a reusable team ("POD"). Not in the current MVP scope — would need its own assumption and acceptance criteria if pursued later.
  4. 4 Private / discoverable toggle. A possible analog for this platform's tenant scoping — check against the existing multi-tenancy model (ADR-025) before adopting as-is.
  5. 5 Gated primary action. "Start" stays disabled until at least one Engineer is selected — a validation pattern worth carrying into whatever collaborator-adding flow this discovery lands on.

# Test Plan: dmcb-s1 — document matrix spurious/duplicate column bugs

**Track:** Short-track (production bug, live-confirmed and root-caused)
**Reported:** operator, live on `skills-framework.fly.dev/features/2026-06-22-wuce-multi-tenancy` — "much more than usual set of artefacts... table is much wider than usual... odd set of extra columns... repeated in all features I just spot checked"

## Root cause (confirmed via live DOM inspection + code trace, not assumed)

Live table markup fetched directly from production confirmed two distinct, compounding bugs in `src/web-ui/routes/features.js`'s document-matrix rendering pipeline (`_buildGroupedFromTrace` → `_extractEpicDocs` → `renderArtefactMatrix`), both introduced by the `canonical-artefact-trace`/`fadm-s1` work (2026-09-06/07):

**Bug A — epic documents explode into one spurious column each.** `artefact-trace.js`'s `walkDir` tags any file under `artefacts/<feature>/epics/*.md` with `type: 'epics'` (the subdirectory name). `_buildGroupedFromTrace` (features.js:471) only routes `type === 'feature-level'` artefacts to `featureLevel`, which is the only array `_extractEpicDocs` ever inspects — so `type: 'epics'` artefacts never reach it. They fall through `_buildGroupedFromTrace`'s remaining branches (no story slug matches an epic doc's filename; `inferGroups` never assigns a shared prefix since every epic doc's filename is unique) into the shared "Unregistered" catch-all story bucket. From there, `_deriveMatrixColumn` has no `SUBDIR_KEY` entry for `'epics'`, so it falls back to using each file's own basename as its column key — one distinct column per epic document. Confirmed live: `2026-06-22-wuce-multi-tenancy` has 9 real epic docs (`epics/phase-0-authorization-guard.md` through `epics/sprint-5-beta-assessment.md`, matching `pipeline-state.json`'s 9 real epic slugs exactly), producing exactly 9 spurious columns, alphabetically sorted, matching the live table precisely.

**Bug B — a duplicate "Story" column.** `renderArtefactMatrix` always renders a hardcoded `<th class="doc-matrix__story-col">Story</th>` first. Any story whose own `stories/<slug>.md` definition file is among its artefacts (true for essentially every registered story in this repo) maps via `_deriveMatrixColumn`'s `SUBDIR_KEY['stories'] = 'story'`. Since `'story'` is also the first entry in `MATRIX_COLUMN_ORDER`, it lands in the computed `columns` array and renders a second, redundant `<th>Story</th>` with just a checkmark link to the story file. This explains the operator's "repeated in all features" observation — Bug A only shows on features with an `epics/` directory, but Bug B affects virtually every feature with any registered story.

**Existing test-coverage gap, confirmed:** `tests/check-fadm-s1-document-matrix.js`'s AC4 tests exercise `renderGroupedArtefactIndexHtml` with a hand-constructed, already-correctly-shaped fixture (`featureLevel: [{ path: '.../epics/e1-something.md', type: 'epic' }]`) — this proves `_extractEpicDocs` works correctly *given* a correctly-routed input, but never exercises `_buildGroupedFromTrace`'s own real branching logic that decides whether a `type: 'epics'` artefact actually reaches `featureLevel` in the first place. That integration gap is exactly what let Bug A ship. No existing test constructs a `stories/<slug>.md`-typed artefact for AC2's column-union test, so Bug B was never exercised either.

## Fixes

1. `_buildGroupedFromTrace` (features.js:471): route `type === 'epics'` artefacts to `featureLevel` alongside `type === 'feature-level'`, so `_extractEpicDocs` gets the chance to correctly claim them by path (it already has correct matching logic — it just never received the right input).
2. `renderArtefactMatrix`'s column computation (features.js:618-619): exclude `'story'` from the computed `columns` array, since the hardcoded first column already covers it.
3. **Discovered during implementation, not in the original plan:** excluding `'story'` from `columns` alone silently dropped every document that mapped to that key from the rendered link count — caught immediately by the pre-existing `check-cat-s4-features-page-integration.js` real-data regression test (`2026-04-19-skills-platform-phase4`, 205 real on-disk files, asserts none are silently dropped: first pass dropped 27, an intermediate fix dropped 22). Fixed properly by folding the excluded documents' links into the existing story-name cell instead of just discarding them: a real per-slug story row normally has exactly one such file, which becomes the name's own link; a synthetic bucket (the shared "Unregistered" catch-all, or an inferred-group bucket) can legitimately hold several such files with no single name to fold into, so each renders its own tick-link appended after the plain-text bucket name. The golden fixture (`tests/fixtures/cat-s4-golden-fadm-output.html`) was regenerated to match — it only ever guarded cat-s4's own refactor against behaviour drift (already proven, historical), not this repo's intended long-term matrix behaviour, so updating it here is legitimate, not a suppressed regression.

## Tests

- **T1 (regression, Bug A, unit level):** `_buildGroupedFromTrace` given a realistic `type: 'epics'` artefact at `epics/<epicSlug>.md` places it in `grouped.featureLevel`, not in any story's artefacts and not in a synthetic catch-all bucket.
- **T2 (regression, Bug A, end-to-end):** the full pipeline (`_buildGroupedFromTrace` → `renderGroupedArtefactIndexHtml`), given a realistic multi-epic trace matching the real `wuce-multi-tenancy` shape (several epics, each with its own `epics/<slug>.md` doc and >=1 registered story), renders a header row with **only** the known abbreviation columns — zero epic-name columns — and each epic's own doc link still appears correctly in its divider row (regression guard against breaking the feature this bug's own fix depends on).
- **T3 (regression, Bug B):** the full pipeline, given a story whose artefacts include its own `stories/<slug>.md` file alongside other document types, renders **exactly one** `doc-matrix__story-col` header cell — not two.
- **T4 (regression, existing coverage unchanged):** `check-fadm-s1-document-matrix.js` and `check-cat-s4-features-page-integration.js` continue to pass unchanged — these fixes must not alter any already-correct behaviour those suites assert.

No CSS-layout-dependent ACs — everything here is assertable via server-rendered HTML string/DOM checks, consistent with this file's own established test convention.

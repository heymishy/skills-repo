# Decisions: placeholder journey left on disk (jpor-s1)

## D1. Skip the disk save for the placeholder instead of cleaning it up afterwards (2026-11-21)

**Context:** `handlePostProductFeature` creates a journey with the placeholder slug `pending` (it needs the journey id to build a fallback slug), and `createJourney` saves it to `workspace/journeys/pending/` at once. `setJourneyFields` then saves it to its real directory, leaving the `pending` directory behind with no tenant. The dashboard shows untagged journeys to every tenant, so each tenant's in-progress count is one too high; the `dsa-s2` spec found it.
**Decision:** `createJourney` takes an optional third argument; with `{ skipDisk: true }` it does not call the disk adapter. The placeholder call passes it. The first disk save of that journey is then `setJourneyFields`, which already runs straight after with the real slug, tenant and product.
**Rationale:** the defect is a write that should not happen, so stopping the write is the smallest change; it deletes nothing, cannot remove a directory that belongs to something else, and leaves every other caller untouched (default behaviour is identical). Journey creation and the field update are consecutive synchronous steps apart from one awaited date lookup, so no reader needs the placeholder on disk.
**Alternatives rejected:** removing the old directory when the slug changes in `setJourneyFields` (a file deletion on disk, riskier, and it would also have to guess which directories are safe to delete); making the dashboard ignore untagged journeys (a wider behaviour change that would hide legitimate legacy journeys from everyone, and it leaves the orphan on disk); giving `createJourney` a tenant argument (the tenant is known, but the slug is not, so a placeholder directory would still be written); changing the `dsa-s2` spec to tolerate one extra journey (hides a real defect, and the expected counts in the spec are correct).
**Operator go-ahead (2026-11-21, "Next spec item", then the choice "Short-track product fix"):** take `dsa-s2` next, and fix the product defect it exposed rather than work around it.

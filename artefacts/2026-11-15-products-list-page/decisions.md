# Decisions - pls-s1 (products list page)

---
**2026-11-15 | FINDING | "See all products" links to /dashboard by design; there is no products list page**
**Evidence:** src/web-ui/utils/html-shell.js lines 106-114 render `<a href="/dashboard">See all products</a>` (pan-s1 comment: it "replaces Home's old role"); server.js has no bare `/products` route; `/dashboard` is handled by `handleGetDashboard` (routes/products.js line 2923), which shows the home page with product cards, pending actions and recent work. Clicked while already on /dashboard the link appears to do nothing, and error capture correctly sees nothing (a normal 200).
**Decision (operator, in chat):** option 1, a dedicated `/products` list page, and the link points to it.
**Open question, same report:** the operator no longer sees the skills-framework product in their product list. Every list (sidebar, dashboard) comes from `SELECT ... FROM products WHERE tenant_id = $1` with the session's tenant, so the likely cause is that the product's `tenant_id` no longer matches the tenant the login resolves to (production has `TENANT_ORG_ALLOWLIST` set, so the session tenant is resolved from the organisation allowlist). Needs a read-only production check of the products table, with the operator's explicit approval first; no production read has been run for this.

**2026-11-15 | VERIFICATION | read-only production check of the products table (operator-approved): the skills-framework product exists in the right tenant**
**Method:** one read-only query run once inside the production app container (`BEGIN READ ONLY`, rolled back, nothing written, credential never left the container); tenant ids that look like emails or numbers masked.
**Result:** 7 products in total. Five belong to tenant `heymishy`, which is the tenant the operator's session resolves to (the earlier bootstrap log lines and the only team_memberships tenant are `heymishy`): `skills-framework` (created 2026-07-20, 18 journeys), `lending app` (5), `name` (4), `List aoo` (1), `New product` (1). Two belong to other tenants and are correctly invisible to this operator. `journeys` by tenant: heymishy 35 (6 without a product), 7 untagged legacy journeys (no tenant), one other tenant 1.
**Conclusion:** the missing-product report is NOT a tenant mismatch or lost data. The sidebar and dashboard lists are `WHERE tenant_id = session tenant` ordered newest first with no limit, so skills-framework should appear (fourth in the list). The remaining explanation is in the page being viewed: `renderProductsSection` returns an empty string when the page did not pass `products` to the shell (html-shell.js line 144), and pan-s1's own comment says only the dashboard, product view and journey pages passed it originally; pncg-s1 added `renderShellWithNav` to fix this, but any page that still calls `renderShell` directly shows NO Products section and NO See all products link. Which page the operator was on when the product was missing is not yet known.
**Next:** ask the operator which page and what they saw; with approval view it in the operator's own browser session; the new /products page (pls-s1) would also give a stable place to find every product.

## `dsa-s2` Task 3 code-quality review: strict tenant-ID equality would have silently hidden untagged legacy journeys — fixed to match the real established convention (2026-09-19)

**Context:** Task 3's implementer wrote the dashboard's journey-tenant filter as `req.session.tenantId ? allJourneys.filter(j => j.tenantId === req.session.tenantId) : allJourneys` — a plain strict-equality filter. Task 3's own code-quality reviewer found this diverges from this codebase's real, already-established tenant-scoping convention (`routes/artefact.js`'s own real pattern: `!(journey.tenantId && journey.tenantId !== tenantId)`), and confirmed via direct code read that `journey-store.js` genuinely defaults `tenantId` to `null` for journeys created before tenancy existed (`diskJourney.tenantId || null`). Strict `===` against a real session `tenantId` would silently exclude every such untagged/legacy journey for any tenant-scoped user — they'd see 0 in-progress sessions and an empty recent list even when real journeys exist, with no error or indication anything was filtered.
**Decision:** Fixed directly to match `artefact.js`'s real, already-correct convention: `allJourneys.filter(j => !(j.tenantId && j.tenantId !== sessionTenantId))` — a journey is only excluded when it HAS a tenantId that mismatches; an untagged journey stays visible to every tenant (matching the intent that pre-tenancy data belongs to no one tenant specifically, not that it belongs to nobody). Verified the corrected semantics directly (`node -e` with a same-tenant/other-tenant/untagged fixture) before committing.
**Rationale:** This is a real correctness bug, not a style preference — two files in the same codebase reading the same journey shape for the same class of access-control decision had genuinely different, incompatible semantics. Fixing it directly (not deferring) closes the gap before it could ship; the fix is a one-line, well-understood change matching an already-proven pattern, not a new design decision.
**Story:** dsa-s2 — no AC or scope change; Task 3's own implementation corrected before it was ever merged.

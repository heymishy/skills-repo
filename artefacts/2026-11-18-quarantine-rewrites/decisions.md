# Decisions: rewrite three quarantined browser specs (qrw-s1)

**2026-11-18 | DECISION | Rewrite each spec to reach the page the way a person or the page's own code does, and keep what each test set out to prove**
**Context:** reference-upload, dsda-s1 and iwu2 were quarantined on 2026-11-17 because the product moved and the specs did not (reasons in `tests/e2e/capability-matrix.json`). The 15 of 16 tests that fail on master all fail on the way in or on a renamed element, not on a broken capability.
**Decision:** reference-upload creates a journey through the CSRF-protected `POST /api/journey` the home page uses and opens `/journey/:id/reference-modal` directly. dsda-s1 asserts the redirect after definition is the review session and opens `/journey/:id/stories` directly. iwu2 asserts the assumption section against an ideate session (the only layout that has it) and the draft section against `#artefact-panel` on discovery. All three move to the core lane with the quarantine fields removed.
**Rationale:** the capabilities still exist (modal, upload, reference page, editable story list, right-panel regions); only the entry or the markup changed. Driving the target page directly keeps each test about its own subject and not about navigation that other specs cover.

**2026-11-18 | DECISION | Three assertions changed meaning, not just selector**
- reference-upload T15 used to assert only that `GET /api/journey?featureSlug=...` did not return 500, which proves nothing about the upload (its own comment called it best-effort). It now asserts the uploaded file name appears on the journey's `/reference` page.
- iwu2 AC4 asserted `max-height:42%` on `#assumption-cards`. Since dsa-s4 the cap is `flex:0 0 38%` on the wrapping `#sw-ideate-assum-group`; the test asserts that. AC7's second element is `#canvas-panel` (the old `#draft-content` is gone). The draft section is `#artefact-panel`, labelled "Artefact draft".
- dsda-s1 asserted the redirect after definition was `/journey/:id/stories`; it is now the review chat. The story's own AC3 (an editable textarea whose edited value proceeds) is unchanged.

**2026-11-18 | OBSERVATION | The reference modal has no entry in the journey form, and a chat page opened on a bare JSON-API session logs a TypeError**
- Nothing in `src/web-ui` links to `/journey/:id/reference-modal` or emits the new-product checkbox the original spec looked for. The modal is reachable only by URL. This is a product question (is the modal meant to be reachable?), not a test one; recorded here and left alone.
- A session created with `POST /api/skills/:name/sessions` has no `turns` array. When its chat page auto-sends the first turn the server logs `TypeError: Cannot read properties of undefined (reading 'length')` at `handlePostTurnStreamHtml` (`routes/skills.js`, the `session.turns.length === 0` check) and the auth guard swallows it. The iwu2 assertions are about the page's markup and pass regardless, and the original spec created its sessions the same way. Sessions created by the page's own routes carry `turns`. Not fixed here (out of scope: nothing under `src/` changes in this story); a bare API session is not a path a person takes.

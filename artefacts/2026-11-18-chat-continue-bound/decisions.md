# Decisions: bound the chat page's hidden continue turns (ccb-s1, issue 1148)

**2026-11-18 | DECISION | Bound the hidden "continue" chain in the page script: 2 for a reply missing a question, 5 for a truncated one, and stop on an identical reply**
**Context:** the chat page re-sent a hidden "continue" turn whenever a streamed turn was not done and its text had no question mark (or the server flagged it truncated), with no bound. In the browser test server a reply without a question mark made every fresh page send 7 to more than 10 turns in 10 to 15 seconds with the send button disabled (lpw-s5); a real model that answers a statement does the same, spending tokens each turn. icv-s1 had fixed the same loop for the ideate skill by exempting it.
**Decision:** two page-level values (`_contChain`, `_lastTurnText`) in the embedded script. A turn the operator sends resets both. A continue is scheduled only while `_contChain` is below 2 (below 5 when the turn was truncated) and the turn's text differs from the previous turn's text. Past the bound the last reply is shown (a hidden continue's text was hidden), the input is re-enabled, and one line says: "Stopped asking the model to continue automatically. Reply below, or send a message to carry on."
**Rationale:** the model's habit that motivated the nudge (an artefact turn that stops short) needs one or two continues at most for a missing question, and a few more when the provider truncated a long artefact; an identical reply means the chain is stuck. The caps are a product decision made here and are the first thing for the reviewer to confirm. The worst case is now 3 model turns (6 when truncated) instead of unbounded.
**Not changed:** the server's truncation detection and SSE events, the ideate exemption, the mock gateway, rate limiting.

**2026-11-18 | NOTE | The page-level variables sit at the top of the script, not next to `sendTurn`**
`tests/check-sccf-s1-show-commit-link-csrf-field.js` extracts `showCommitLink()` with a pattern that expects `sendTurn` to follow it directly, so declarations placed between them broke that test; they are declared at the top of the script instead.

**2026-11-18 | CORRECTION | The "no product code changed" checks added in lpw-s4 and lpw-s5 were removed from their permanent tests**
Both `tests/check-lpw-s4-seed-team-member.js` (T5) and `tests/check-lpw-s5-stub-turn-ends-on-question.js` (T5) compared the branch's diff with master. That held for the pull request that added each, but it fails any later pull request that touches `src/web-ui/routes/`, `modules/` or `public/` (this one did), so it would have broken unrelated work. Those acceptance criteria (AC5 of each story) were verified by reading the diff at review and are recorded as such in their Definitions of Done; a branch-relative check does not belong in the suite that runs on every pull request.

# Spike Brief: Journey-map CX/UX best practice vs. canvas+CX-tab convergence

**Opened:** 2026-10-11 | **Scope:** Standard (up to 6 steps) | **Blocking:** `/discovery` for the new `2026-10-11-journey-cx-redesign` initiative (not yet saved — paused mid-Section-1 to run this spike first, per operator request)

---

## Question

What does CX/UX best practice say about journey-map structure and visual design (swimlane/grid layout, emotion curves, persona framing, per-stage illustration), and how should that inform converging the free-form canvas (`ic-s1`–`ic-s4`, a `drawflow.js` node-and-connector diagram) and the existing Customer experience tab (a swimlane-shaped page showing emotion/pain-points/opportunities per stage as plain text) toward a single, more polished journey-map format?

## Type

3 — Design decision (which of two or more approaches should we take)

## Scope

Standard — multiple sources, up to 6 research steps. If the done condition was met before the limit, stop early.

## Done condition

A written synthesis of journey-mapping best practices (common structural patterns, when a swimlane/grid format is right vs. a free-form node graph, which visual elements carry the most UX value), plus a concrete recommendation — with trade-offs — for how the canvas and CX tab should converge.

## Out of scope

- Actual UI mockups/visual design (`/design`, downstream of this)
- Re-litigating the `drawflow.js` canvas library choice itself (already decided, `ic-s1`'s own `decisions.md`)
- Implementation planning

## Outcome options

- **PROCEED:** generic best practice confirms the free-form canvas, restyled, is a reasonable journey-map format — continue discovery assuming a single converged view.
- **REDESIGN:** best practice points to a different structural approach than either current view alone — discovery framing needs to change before continuing.
- **DEFER:** the question cannot be answered from available sources — name what's missing and who to consult.

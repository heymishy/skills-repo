## Unit Tests

### staticParsingExtractsTableColumnRelationshipFromRealMigrationFileFormat
- **Verifies:** AC1
- **Precondition:** A synthetic migration file fixture with 2 tables and a foreign-key relationship, in this repo's real migration-file format
- **Action:** Run the static parser
- **Expected result:** The parser correctly extracts both tables, their columns, and the relationship
- **Edge case:** No

### staticParsingHandlesMultipleMigrationFilesForOneFeature
- **Verifies:** AC1
- **Precondition:** A feature with 2 separate migration files touching related tables
- **Action:** Run the static parser across all of the feature's migration files
- **Expected result:** A single, coherent as-built diagram combining entities from both files
- **Edge case:** Yes — the multi-file aggregation case

### callGraphExtractionReflectsRealMergedCodeStructure
- **Verifies:** AC2
- **Precondition:** A real, already-merged feature's file structure and call graph (from this session's own delivery)
- **Action:** Run the as-built System Architecture/Program Design generation
- **Expected result:** The generated diagram's structure matches the real file/call relationships as they actually exist in the merged code — not a re-prompted agent's approximation
- **Edge case:** No

### asBuiltGenerationDoesNotRePromptAgentForDescription
- **Verifies:** AC2
- **Precondition:** Same as above
- **Action:** Inspect the generation implementation
- **Expected result:** The generation logic reads real files/AST structure directly — it does not send a prompt asking an agent "what did you build" and use the agent's free-text answer as the diagram source
- **Edge case:** No — this is the specific anti-pattern discovery explicitly rejected (an agent re-describing from memory)

### malformedMigrationFileFailsWithClearErrorNotSilentEmptyDiagram
- **Verifies:** AC4
- **Precondition:** A deliberately malformed SQL fixture
- **Action:** Run the static parser against it
- **Expected result:** A clear, specific error is raised (naming the file and the parse problem) — the process does not silently produce an empty or incorrect diagram
- **Edge case:** Yes — this is the negative-case test

### malformedMigrationFileErrorSurfacedToOperatorNotSwallowed
- **Verifies:** AC4
- **Precondition:** Same as above
- **Action:** Run the full `/verify-completion` flow with the malformed fixture present
- **Expected result:** The operator sees the error in the session output — it is not caught and silently discarded
- **Edge case:** No

## Integration Tests

### asBuiltGenerationRunsWithinVerifyCompletionSession
- **Verifies:** AC1, AC2
- **Components involved:** `/verify-completion`/`/branch-complete` skill flow, static parser, diagram generation
- **Precondition:** A real, merged feature ready for `/verify-completion`
- **Action:** Run `/verify-completion`
- **Expected result:** As-built diagrams (all three types) are generated as part of the normal session flow, without a separate manual trigger

### asBuiltDiagramsWrittenAsVersionedArtefactFiles
- **Verifies:** AC3
- **Components involved:** `/verify-completion` output, feature artefact folder
- **Precondition:** As-built diagrams generated for a test feature
- **Action:** Inspect the feature's artefact folder after the session
- **Expected result:** As-built diagram content exists as saved files in the artefact folder (not only held transiently in session memory) — consistent with this repo's artefact-first convention

## NFR Tests

### migrationParsingCompletesWithinNormalSessionTimeBudget
- **NFR addressed:** Performance
- **Measurement method:** Time the static parsing step for a representative feature (5-10 migration files)
- **Pass threshold:** No separate long-running background job needed — completes within the same session, no numeric target set (no baseline exists)
- **Tool:** Manual timing observation during dogfood use

### asBuiltGenerationEventsAreLogged
- **NFR addressed:** Audit
- **Measurement method:** Run as-built generation; check logs for an entry recording the feature, diagram types generated, and success/failure
- **Pass threshold:** A log entry exists for every generation attempt, success or failure
- **Tool:** Log inspection

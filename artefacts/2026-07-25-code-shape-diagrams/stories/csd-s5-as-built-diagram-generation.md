# Story: As-built diagram generation via static migration-file parsing

**Epic reference:** artefacts/2026-07-25-code-shape-diagrams/epics/csd-e1-code-shape-diagrams.md
**Discovery reference:** artefacts/2026-07-25-code-shape-diagrams/discovery.md
**Benefit-metric reference:** artefacts/2026-07-25-code-shape-diagrams/benefit-metric.md

## User Story

As a **Developer/engineer**,
I want **`/verify-completion` and/or `/branch-complete` to generate as-built diagrams (all three types) by parsing the real, committed code and migration files**,
So that **I have a real record of what was actually built, not just what was planned**.

## Benefit Linkage

**Metric moved:** P1 — Time-to-drift-determination; P2 — Diagram completion rate; M1 — Drift caught before it became a problem.
**How:** This is the "as-built" half the whole epic's value proposition depends on — without a trustworthy as-built diagram, csd-s6's drift check has nothing real to compare the design against.

## Architecture Constraints

- ADR-027: this story is the skill-governed half of the split — diagram generation runs inside an operator-driven `/verify-completion`/`/branch-complete` session, distinct from csd-s2's app-code rendering.
- Per discovery's resolved decision (see `decisions.md`): as-built Data Model diagrams derive from static parsing of the repo's actual committed SQL/migration files, not live-database introspection.
- Uses csd-s2's rendering mechanism for display; this story is responsible for generation only.

## Dependencies

- **Upstream:** csd-s2, csd-s3, csd-s4 (the rendering mechanism and as-designed diagrams must exist first, so csd-s6's drift check has both halves to compare).
- **Downstream:** csd-s6.

## Acceptance Criteria

**AC1:** Given a feature has merged with real committed SQL/migration files, When `/verify-completion` or `/branch-complete` runs, Then an as-built Data Model diagram is generated by parsing those actual migration files — static analysis, no live database connection.

**AC2:** Given the same feature's real merged code (call graph, file structure), When the inner loop runs, Then as-built System Architecture and Program Design diagrams are generated reflecting the actual implementation — not a re-prompted agent's memory of what it built.

**AC3:** Given the as-built diagrams are generated, When saved, Then they are written to the feature's artefact folder as versioned files, consistent with this repo's artefact-first convention — not just displayed transiently in a session.

**AC4:** Given a feature where the migration files cannot be parsed cleanly (e.g. malformed SQL, unsupported migration format), When as-built generation runs, Then it fails gracefully with a clear error surfaced to the operator, rather than silently producing an empty or incorrect diagram.

## Out of Scope

- Live-database introspection — discovery's own out-of-scope item, deferred to a later confirmation step.
- Real-time or continuous as-built regeneration outside of `/verify-completion`/`/branch-complete` — this is a point-in-time snapshot at inner-loop completion, not a live-updating view.

## NFRs

- **Performance:** Migration-file parsing completes within the normal `/verify-completion` session time budget — no separate long-running background job for the MVP.
- **Security:** Same "structure only, never row-level data" constraint as csd-s4.
- **Accessibility:** Inherits csd-s2's accessibility properties.
- **Audit:** As-built diagram generation events are logged (which feature, which diagram types, success/failure), consistent with this repo's general logging conventions.

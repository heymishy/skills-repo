## Story: A production-wiring smoke test that boots the real app and sweeps every route with hostile input

**Status:** DRAFT for operator review. Not yet through `/test-plan` or `/definition-of-ready`.
**Epic reference:** None - short-track (CI hardening, per CLAUDE.md's short-track path)
**Discovery reference:** None. Evidence: `artefacts/2026-11-15-production-error-sweep/reference/ci-regression-scenarios-audit.md` (the wiring gap) and sweeps 2 and 3. Every real bug those found (unwired `getCommitResult` and `submitAnswer`, 503 and 500 on odd URLs, commit-preview on an unknown session, turns accepting garbage) passed an 866-file suite because tests wire their own adapters.
**Benefit-metric reference:** None - short-track
**Domain:** [web-ui, ci]

## User Story

As **the operator merging pull requests**,
I want **one CI check that runs the application with its real production wiring and probes every route with bad input**,
So that **an unwired adapter, a route that answers 5xx to a bad request, or an unvalidated body is caught on the pull request instead of in production**.

## Benefit Linkage

**Metric moved:** None formal. Catches the class of defect that produced all of this week's production errors and issue #1121, on the PR's own code, in about a minute, replacing the coverage the staging end-to-end gives (which tests master, not the PR).
**How:** a plain Node test (`tests/check-pws-s1-production-wiring-smoke.js`) starts `createApp()` in-process with `WIRE_SKILL_ADAPTERS=true` and the mock model, signs in a seeded test session, derives the route list from the real route table, and runs the sweep from sweeps 2 and 3 automatically.

## Architecture Constraints

- **Real wiring, not test doubles:** the test must not call any `set...` adapter itself. It loads `server.js` exactly as production does (the `WIRE_SKILL_ADAPTERS` branch) so an adapter that the server forgot to wire stays unwired and the test sees the failure.
- **Adapter wiring check:** every injectable adapter module exports a way to ask "is this still the throwing default?" (or the test calls each adapter once and treats `Adapter not wired:` as a failure); the list is derived by scanning `src/web-ui/adapters/*.js` for the `Adapter not wired` stub, not hand-maintained.
- **Route sweep:** GET and POST shapes are derived from the route table or a checked-in route manifest generated by a script (decision at test-plan time); each id segment is replaced with: `not-a-uuid`, `%00`, `%E0%A4%A`, a well-formed unknown uuid, a 300-character value and an encoded traversal; bodies are none, `{bad`, `[]` and a nested object. Assertion: no response status is 5xx, no response contains `Adapter not wired` or a stack trace, and no unknown-id GET returns 200 with a form.
- **Safe by construction:** runs against the in-process app with no database and no network (existing fake-db and GitHub stubs); no real GitHub, Stripe or model call; routes that write outward (billing, repo create, commit, sign-off) are exercised only with invalid input and with their outward adapters stubbed to throw if called.
- **Known-bug handling:** while `sub-s1` and `cpv-s1` are unfixed the test must either skip those two routes with a named, expiring allow-list entry or be merged after them; an allow-list entry without a story id fails the test.
- **Budget:** under 60 seconds on a CI runner.
- Zero new npm dependencies.

## Acceptance Criteria

**AC1:** Given the real server wiring, When any injectable adapter is still its throwing default after startup, Then the test fails and names the adapter.

**AC2:** Given every discovered route shape, When it is requested with each hostile id and body, Then no response is 5xx, none contains `Adapter not wired` or a stack trace.

**AC3:** Given the sweep, When an unknown id on a read route returns 200 with a form or page body, Then the test fails and names the route.

**AC4:** Given today's master, When the test runs, Then it reports exactly the known open defects (`sub-s1` `/answer`, `cpv-s1` commit-preview) and nothing else, each via an allow-list entry with a story id.

**AC5:** Given a deliberately reintroduced defect (a test-only mutation: unwire one adapter), When the test runs, Then it fails (a self-check that the test can fail).

**AC6:** Given a clean run, When CI executes it, Then it completes in under 60 seconds and is part of the existing unit chain.

# Decisions: collapsed group tab order (ctab-s1)

## D1. Hide collapsed group bodies with a delayed `visibility` rule, in CSS only (2026-11-20)

**Context:** a collapsed group on the product view is hidden only by `grid-template-rows: 0fr` and `overflow: hidden`, so its links and buttons stay in the tab order and the accessibility tree. A local probe found 6 of 78 Tab stops inside collapsed groups. Every script that opens or closes a group (`a4ToggleModule`, the search auto-expand, bulk assign) toggles the class `a4-module-body--collapsed`.
**Decision:** add `visibility: hidden` to `.a4-module-body--collapsed`, with `transition: grid-template-rows 0.25s ease, visibility 0s linear 0.25s` so it applies only after the collapse animation; the base `.a4-module-body` rule keeps `visibility: visible` and a zero-delay transition, so expanding shows the content at once. No markup or script change.
**Rationale:** one CSS rule covers all three scripts and any future one that toggles the class, keeps the animation, needs no change to the markup, and is supported everywhere. The header button stays outside the body, so it remains the way in.
**Alternatives rejected:** the `inert` attribute set by the three scripts (more code in three places, and a new script path to forget); `display: none` when collapsed (kills the height animation, which `a4-module-expand-collapse` measures); `tabindex="-1"` on each child (misses new children and leaves the content visible to screen readers); expanding groups by default (a product decision, not an accessibility fix).
**Operator go-ahead (2026-11-20, "1 then two"):** to short-track this story first, then the test-isolation story.

## D2. The new spec goes in the `extended` lane of the capability matrix, not the core (2026-11-20)

**Context:** `tests/check-lpw-s2-capability-matrix.js` requires every spec file under `tests/e2e/` to appear once in `tests/e2e/capability-matrix.json` with a capability and a lane (core = blocking Core browser tests job, extended = non-blocking all-specs job, scenario, quarantined). The first CI run of the pull request failed on exactly this (`tests/e2e/ctab-s1-collapsed-group-tab-order.spec.js: spec file is missing from the matrix`); the DoR contract had not listed the matrix as a touchpoint, so it is added here. Locally, running the new spec in parallel with `ep2-s1` or `ep2-s2` made an `ep2` spec fail 3 times out of 3, and `ep2-s2` is in the core lane; the same happens on master with `frsr-s1` alone.
**Decision:** add one entry, capability `accessibility-and-responsive`, lane `extended`, with the reason above. Do not move any other spec.
**Rationale:** a spec that passes alone belongs in `extended`; putting a spec that disturbs a core spec into the blocking core lane would make the blocking job less reliable. It moves to the core once test isolation is fixed (the next story).
**Not done here, found while doing it:** the five specs repaired in esh-s1 (`ep1-s3`, `ep1-s4`, `fpux.1`, `jcx-s6`, `frsr-s1`) are all lane `quarantined` in this matrix with reasons recorded on 2026-11-17 that are now wrong (for example "a product-side difference" for `ep1-s3` and `jcx-s6`, and "needs a repository rollup" for `frsr-s1`). They pass now, so their entries should move out of quarantine; that is a separate, small change and the operator's call on the lane (extended, or core, which would make them blocking).

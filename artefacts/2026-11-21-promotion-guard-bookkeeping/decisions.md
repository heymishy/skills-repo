# Decisions: promotion guard and bookkeeping commits (pgb-s1)

## D1. Accept a run behind the head only when every commit in between is bookkeeping; keep failing closed (2026-11-21)

**Context:** spg-s1's guard refuses any promotion whose run commit is not exactly the head of master, to stop an old waiting run from putting old code over newer production code. Bookkeeping pushes (artefacts, state) start no deploy run because the workflow ignores those paths, and the repository rule is to push them after each code merge, so a run's commit is behind the head almost immediately. On 2026-11-21 the operator approved run 44873189915 and the guard refused it although the six files after it were all bookkeeping.
**Decision (operator, 2026-11-21, "Fix the guard, and I hold bookkeeping meanwhile"):** when the run commit is not the head, the guard compares the two commits through the GitHub API and accepts only if the head is strictly `ahead`, the lists are complete, and every changed path, and the previous name of every renamed path, is a bookkeeping path from one shared list that a test keeps equal to the workflow's `paths-ignore`.
**Rationale:** the guard's purpose is to refuse stale code, not stale bookkeeping; the same ignore list already decides that these paths need no deploy, so using it here is consistent; every doubt (a failed comparison, truncation, divergence, an unwired adapter) refuses, which is the direction that cannot ship stale code.
**Alternatives rejected:** hold all bookkeeping pushes until each promotion is approved (fragile and contrary to the repository's own post-merge rule; kept only as an interim measure by the agent until this merges); make the promote job deploy the head instead of its own commit (changes what is built and deployed in production and skips the staging evidence for that exact commit); remove the guard (loses the protection it was written for).
**Risk accepted:** a bookkeeping path could in principle affect runtime (for example `workspace/` data read by the app). The deploy workflow already treats these paths as needing no deploy, so the guard inherits that assumption; `artefacts/*/playback/**`, which the app serves, is excluded from the list on purpose.
**Operator note (2026-11-21):** the operator's approval of run 44873189915 was wasted by the refusal; the agent had pushed bookkeeping commits before reporting that run as waiting, which made it unpromotable. Recorded so the sequence is not repeated: until this merges, no push to master after a code merge until the promotion is approved.

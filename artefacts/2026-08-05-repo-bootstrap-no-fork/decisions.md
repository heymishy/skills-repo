**2026-08-05 | ARCH | /definition (rb-s3)**
**Decision:** Harness-agnostic instruction files (`CLAUDE.md`, `AGENTS.md`, `.cursorrules`, `.github/copilot-instructions.md`) are generated by extending the existing copy-based `scripts/assemble-copilot-instructions.sh` (per ADR-005), paired with a new drift-check validator — not by symlinking the files together.
**Alternatives considered:** Symlinks (one real file, others as symlinks pointing at it) — the mechanism the qm reference architecture uses.
**Rationale:** This repo's own dev environment is Windows, where git's symlink support is opt-in (`core.symlinks`) and inconsistent on checkout — a user without it enabled silently receives a plain-text file containing the link path instead of a working symlink, breaking the guarantee with no visible error. A copy-based assembly step plus a drift-check validator recovers the same "impossible to diverge" property without depending on a platform-specific filesystem feature that can silently fail, and extends a mechanism this repo already has rather than introducing a second one.
**Made by:** Hamish King — Platform maintainer / Product owner
**Revisit trigger:** If this repo's primary dev environment ever shifts away from Windows, or if git's Windows symlink support becomes reliable-by-default, symlinks could be revisited as a simpler alternative.

**2026-08-05 | ASSUMPTION | pre-/test-plan re-check (rb-s1, rb-s2, rb-s4)**
**Decision:** `scripts/platform-init.js`, `platform-fetch.js`, `platform-pin.js`, and `platform-verify.js` already exist in this repo (built as stories i1.2/i1.3, PRs #242/#245, in an earlier Phase 1 distribution initiative) and already implement file-copy, update-fetch, and hash-pin/verify against a target directory. rb-s1, rb-s2, and rb-s4 are revised to wrap and extend these existing scripts rather than reimplement their logic. The core problem discovery identified — no way to reach this tooling without a local clone of the source repo — remains real and unsolved by the existing scripts, since all four default `PLATFORM_ROOT`/`scriptRoot` to their own repo checkout; only the packaging/reachability layer (an npm-installable `npx` entry point) is still missing.
**Alternatives considered:** Leave the stories as originally written and let the coding agent discover the existing scripts during implementation.
**Rationale:** This was found via `/review`→pre-`/test-plan` investigation of `package.json`'s test-runner scripts block, which surfaced `platform:init`/`platform:fetch`/`platform:pin`/`platform:verify` npm scripts unrelated to the immediate question being asked. Writing test plans against stories that assume no prior art exists, when working, tested file-copy/fetch/pin logic already does, would produce misleading technical test plans and risk the coding agent duplicating logic rather than extending it. Caught before /test-plan rather than after.
**Made by:** Hamish King — Platform maintainer / Product owner
**Revisit trigger:** None expected — this is now reflected directly in the affected stories' Architecture Constraints and ACs.

**2026-08-05 | RISK-ACCEPT | /branch-setup baseline (rb-s1)**
**Decision:** Proceed with rb-s1 implementation against a failing baseline of 37 pre-existing test failures (out of 455 files, `node scripts/run-all-tests.js`), rather than fixing them first.
**Findings accepted:** All 37 failures are unrelated to rb-s1's scope (`cli/` entry point, `package.json` bin/files fields, `contexts/personal.yml` seeding, `.github/pipeline-state.json` seeding) — they are pre-existing failures in unrelated feature areas (Neon staging, PostHog, billing portal, several UI panel and journey-store tests requiring live services or unrelated fixtures). Of note: `tests/check-i1.2-platform-init-fetch.js` (2 of 20 tests) fails in this baseline for a pre-existing bug in `platform-init.js`'s own skip/force-reporting behaviour, unrelated to and pre-dating rb-s1 — out of scope to fix per this story's explicit "Do NOT modify `platform-init.js`'s existing behaviour" constraint.
**Alternatives considered:** Halt and fix all 37 pre-existing failures before starting rb-s1.
**Rationale:** None of the 37 failures touch files rb-s1 creates or modifies (`cli/`, `package.json`, `contexts/personal.yml`, `.github/pipeline-state.json` seed shape). Fixing them is a separate, unscoped effort spanning many unrelated features. rb-s1's own new test file is verified in isolation (`node tests/check-rb-s1-*.js`) in addition to the full suite run, so its own correctness is not obscured by this pre-existing noise.
**Made by:** Coding agent (dispatched inner-loop run) — 2026-08-05
**Revisit trigger:** If any of these 37 failures is later found to share a root cause with rb-s1/rb-s2/rb-s3's shared `scripts/platform-init.js` dependency, re-open and investigate jointly.

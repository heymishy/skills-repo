# Decisions: E2E selector hygiene (esh-s1)

## D1. Repair the five specs on the spec side only, each by the smallest change that restores what it checks (2026-11-20)

**Context:** five of the 16 E2E tests that fail on every CI run were traced to specs, not to the product. Measured on 2026-11-20: `ep1-s3` and `frsr-s1` take `.first()` of a selector whose first match is inside a `display:none` container; `jcx-s6` AC1 counts `.sw-cx-grid-cell--header` and finds 6 where 3 are visible (the other 3 are in the hidden delivery grid, which reuses the class); `ep1-s4` assumes `/journey` holds only the journey it just seeded, but the shared `e2e-tester` tenant held 138 journeys and 123 visible stage dots (none hidden), so scenario 2 matched 8 "Move back to Benefits" links and scenario 3's first dot belonged to another journey's card; `fpux.1` AC2a and AC2b pin hex values of a palette that `html-shell.js` no longer uses (and the dark ink also changed, `#F4F4F2` to `#F5F6F7`).
**Decision:** change only the five spec files. Use `:visible` for the three hidden-duplicate cases. Scope `ep1-s4` to the seeded journey through the id the seed endpoint already returns. Make `fpux.1` compare against the page's own resolved tokens.
**Rationale:** the triage found that `ep1-s4` was assumed to be the hidden-duplicate case; the measurement showed it is shared state, which is a different repair. Scoping to the seeded id is correct however many journeys the tenant holds, needs no data cleanup, and keeps every assertion. Resolving tokens in the page keeps the test meaningful (light and dark must differ and match their own tokens) without freezing a palette that the design system owns and changes on purpose.
**Alternatives rejected:** hiding or removing the duplicate markup in the product (a product change for a test's sake, and the hidden grids are intentional); deleting leftover journeys from the shared tenant (needs a delete path or staging data access, and does not fix the next run's leftovers); updating the hex literals again (breaks again at the next palette change); dropping the failing assertions (weakens the spec).
**Limit stated in the story:** this does not fix test isolation in general (`dsa-s2`, `s3.2`, intermittent specs). It makes `ep1-s4` independent of it.
**Operator go-ahead (2026-11-20, "Yes"):** to short-track this story, after the report that listed the selector fixes first.

## D2. `frsr-s1` opens the collapsed module group first, and a keyboard-accessibility finding is recorded, not fixed (2026-11-20)

**Context:** the first repair for `frsr-s1`, `:visible` on the row link, made the keyboard test pass and the mouse test time out: the only visible row link sits inside a module group that starts collapsed (`products.js` lines 389 to 400, pdt-s1 AC2; `.a4-module-body--collapsed` is `grid-template-rows: 0fr` with `overflow: hidden`). Playwright counts the clipped 686 by 34 link as visible, but the group header intercepts the click.
**Decision:** the spec opens the group first, as a user must (mouse click on the header in the first test; focus and Enter on the header in the second), asserts `aria-expanded="true"`, then acts on the row link inside that group. No assertion is removed; two are added.
**Rationale:** the product behaviour (groups start collapsed) is deliberate and documented in the code; the spec predates it. Opening the group is what a real user does, and the keyboard test now proves a keyboard-only path exists end to end instead of focusing a link nobody can see.
**Finding, not fixed here:** a keyboard user pressing Tab on the product view lands on links and buttons inside collapsed groups (a local probe pressed Tab 80 times: 78 stops, 6 of them inside `.a4-module-body--collapsed`, each a row link, rename button or pods button). Collapsed content that stays in the tab order lets focus disappear into content that cannot be seen. This is a possible keyboard-accessibility defect in the product, outside this story (no product change here). Suggested follow-up for the operator: a short-track bug story that makes collapsed bodies unreachable (for example `inert` or `visibility: hidden` while collapsed, removed on expand) with a spec that Tabs through the page with groups collapsed.
**Alternatives rejected:** keeping `:visible` and clicking with `force: true` (hides the fact that a real click cannot reach the link); expanding the groups in the product by default (a product decision); loosening the keyboard test to pass as before (it was passing for the wrong reason).

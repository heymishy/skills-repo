**2026-10-16 | ARCHITECTURE | fpd-s2 — caption/transcript provider: interaction-sequence-derived, not an external speech-to-text call**
**Decision:** `src/web-ui/adapters/caption-transcript.js`'s own `realGenerateCaptionsAndTranscript` implementation does not call any external speech-to-text/transcription API. It derives captions (timed WebVTT, 4 seconds per step) and a standalone transcript directly from the same scripted interaction-sequence text `fpd-s1`'s own capture already produces per Acceptance Criterion (AC) — each AC's own DoD evidence row — not from audio transcription.
**Context:** The story's own DoR contract named the transcription provider as "an implementation detail the coding agent selects at build time," but no external speech-to-text provider (API key, SDK, network dependency) is confirmed available in this delivery environment — the same kind of unconfirmed-dependency situation the D2-platform gate already caught once for `ffmpeg` (see the 2026-10-15 entry above). AC4 itself independently supports this choice: it requires a transcript "sourced from the scripted interaction sequence and any on-screen text, not from spoken audio that doesn't exist" for a silent recording — meaning the interaction-sequence text was always going to be the primary source of truth for at least some videos, not merely a fallback.
**Rationale:** Choosing the interaction-sequence-text source as the ONLY source (rather than real audio transcription with this as a silent-case fallback) removes an unconfirmed external dependency entirely, keeps the whole mechanism deterministic and fully unit-testable with no network/API-key requirement, and satisfies AC4's own literal wording for every video, not just silent ones. Accuracy-of-transcription guarantees are explicitly out of scope for this story (story's own Out of Scope section) — this implementation does not claim to transcribe spoken narration, only to produce a real, traceable, accessible transcript from the feature's own already-authored evidence text, consistent with that scope boundary.
**Made by:** Claude (session), during `fpd-s2`'s own implementation (Task 2), following the same reasoning the D2-platform gate already established for this feature.
**Revisit trigger:** If a future need arises for literal spoken-narration transcription (e.g. an engineer records real narrated audio and wants it transcribed verbatim, not just the interaction sequence restated), confirm a real speech-to-text provider's actual availability in the delivery environment first, then add it as an additional source alongside (not replacing) the interaction-sequence-derived path — the D37 adapter boundary already supports swapping the wired implementation without touching any caller.
